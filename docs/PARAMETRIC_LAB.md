# Parametric Lab — User Guide

## Purpose

The Parametric Lab is a local graphical test bench for the current Mayhem Building Forge C++ generator. It is a thin user interface over the native executable, not a second implementation of the layout algorithm.

## Requirements

- Windows 10/11
- Visual Studio 2022 C++ workload
- CMake 3.20+
- Git
- Python 3 (standard library only)
- A successful build of `mbf_build_house.exe`, `mbf_topology_preview.exe`, and `mbf_generate_topology_house.exe`

## Start

From the repository root in PowerShell:

```powershell
.\scripts\run_parametric_lab.ps1
```

The launcher builds the native executable if it is missing, then starts the local server. Open:

```text
http://127.0.0.1:8765
```

Keep the PowerShell window open while using the Lab. Press Ctrl+C in that window to stop the server.

## Controls

- Site width/depth: outer site dimensions in metres.
- South/north/east/west setbacks: deducted from the site to calculate the buildable rectangular footprint.
- Entrance facade: south, north, east, or west.
- Floors: the topology-driven solver currently accepts one floor; multi-floor requests are rejected explicitly.
- Bedrooms requested: the experimental topology-driven solver accepts 1–4 bedrooms.
- Bathrooms requested: 1–4 bathrooms.
- Room target areas: living, kitchen, bedroom, bathroom, and hallway areas are independently adjustable within validated ranges. The UI shows the requested total against the buildable footprint.
- Bathrooms requested: 1–4 bathrooms.
- Seed: reproducible generation seed.
- Brief persistence: import/export the current parameter set as JSON.
- Candidate output: compare ranked SVG plans, inspect heuristic metrics, and download individual SVGs.
- Design variations: generate one selected profile or compare all three currently implemented profiles.

When all profiles are requested, the local server invokes the native C++ executable separately for Balanced Conventional, Open Living, and Privacy First. Each successful SVG is shown as a separate candidate card with its generation report. A second panel displays room-adjacency graph candidates generated by the new topology layer. A third panel shows topology-derived plans with walls, entrance, doors, and windows. It also displays heuristic daylight, privacy, circulation, and overall quality scores.

## How the integration works

1. The browser sends the brief to `127.0.0.1`.
2. `scripts/mbf_gui_server.py` validates the request.
3. The local server runs the legacy profile generator, topology graph preview, and topology-driven house generator with explicit command-line arguments.
4. The C++ engine generates room graphs, solves supported graphs into rectangular plans, creates role-aware openings, validates room access, and returns ranked SVG candidates.
5. The server returns the generated SVG and diagnostics to the browser.

The server binds to loopback only. It does not expose a network listener to the LAN or send project data to an external service.

## Furniture layout and editing

The topology-driven SVG preview now contains typed, individually identified furniture instances. The native core places furniture by room function and validates footprints against room polygons and other furniture clearances. In the Parametric Lab, enable furniture editing to select and drag objects, rotate the selected object in 90-degree increments, reset the generated layout, and export the edited SVG. These edits currently live in the exported SVG only; they are not yet persisted into the Building Brief or fed back into native project data. Door-swing, window-access, and continuous circulation-path validation remain pending.

## Current limitations

- The legacy profile generator still generates a fixed five-space, one-bedroom typology; the experimental topology-driven solver supports a configurable 1–4 bedroom schedule.
- The three floor-plan profiles alter zoning ratios but do not yet represent three independent geometric floor-plan topologies. The separate topology graph layer can generate distinct relationship graphs, but those graphs are not yet embedded as room polygons.
- The topology-driven solver currently supports one floor only; multi-floor briefs are rejected explicitly.
- The topology-constrained geometric solver currently uses rectangular guillotine partitions; it is not yet a general polygonal room-shape optimizer.
- Doors and windows are placed heuristically; door swings, furniture clearances, and detailed accessibility checks are not yet modeled.
- Daylight potential, privacy, and circulation scores are explainable heuristics, not full daylight simulation or building-code compliance.
- The GUI is not yet a freeform visual room editor or 3D preview.
- Furniture placement is currently an initial deterministic 2D model; edits export to SVG but are not yet persisted into project data. Door-swing, window-access, circulation-path, and Unreal physics integration remain pending.

The Lab is a development tool. Its output is not a construction drawing or proof of regulatory compliance.

## Troubleshooting

**Generator executable not found:** run the launcher again; it attempts to configure and build the CMake project. If CMake fails, inspect the compiler output in PowerShell.

**Python not found:** install Python 3 and enable the Python Launcher (`py -3`) or add `python.exe` to PATH.

**Browser says it cannot connect:** make sure the PowerShell server window remains open and that the address is exactly `http://127.0.0.1:8765`.

**No valid candidate:** inspect the diagnostic text in the candidate area. A valid Building Brief is not necessarily supported by the current residential solver.
